# BottleMusic 双界面播放器重构设计

日期：2026-07-10  
状态：待用户书面审阅  
范围：前端界面、首页生命周期、播放器控制、歌词普通/全屏布局  

## 1. 背景与结论

本轮不是继续给现有界面“加一点动效”，而是把 Aurora 与 Newsprint 重构为两套具有独立布局语言的界面，同时共享同一套播放、导航、数据与后端能力。

用户截图暴露的核心问题如下：

1. 深色模式进度条的轨道、已播放段和滑块缺少稳定对比度。
2. 自定义标题栏、页面标题和内容区域叠加多条横线，视觉割裂且占用高度。
3. Aurora 与 Newsprint 主要依靠颜色、字体和局部圆角区分，组件结构与信息层级基本相同。
4. “回到当前行”绝对定位在歌词正文上方，会覆盖歌词。
5. 歌词全屏同时保留普通页面标题、全屏按钮、退出全屏按钮和窗口标题栏，造成拥挤与重复操作。
6. 首页返回时会重新出现空状态和内容填充，用户感知为卡顿。
7. 首页推荐播放器占用面积很大，却主要由文字与装饰唱片构成，真实音乐内容密度过低。
8. 底部播放器在两套皮肤中结构相同，控制和进度信息分散，无法承担界面的视觉锚点。

技术诊断确认第 6 点不是 Vue、Tauri 或 GSAP 的性能上限：

- `App.vue` 使用随每次导航递增的 `viewTransitionVersion` 作为视图容器 key。
- 返回首页时，旧 `HomeView` 被销毁并创建新实例。
- `HomeView` 在 `onMounted` 中重新调用 `loadDailyRecommendations`、`loadRecommended`、`loadNewAlbums`。
- 新实例的三个 section state 从空数据开始，因此会出现骨架/空白后再填充的过程。

因此，本设计把“首页保活与稳定视图身份”列为首要架构修复，而不是用更强动画掩盖重新加载。

## 2. 已确认的产品决策

- Aurora 与 Newsprint 是两套独立展示界面，不是同一 DOM 结构的换色皮肤。
- 两套界面共享播放状态、数据加载、导航、错误处理和 Tauri 后端调用。
- 顶部装饰横线全部移除，标题栏、导航和内容背景通过表面层次自然融合。
- 歌词“回到当前行”位于歌词区域最底部的保留操作区，不覆盖歌词。
- 歌词全屏只保留“最小化”和“退出全屏”两个按钮。
- Aurora 参考 Mineradio 的沉浸式视觉舞台和内容聚焦方式，但不复制品牌、素材、粒子特效或 3D 场景。
- Newsprint 保留编辑版面与报刊气质，但不再依赖重复横线制造复古感。
- Aurora 使用有弹性、带果冻感但不拖沓的动效语言；Newsprint 使用更克制的印刷、纸张与排版反馈。
- 继续使用 Vue 3、Tauri 2 与现有 GSAP，不引入 Motion/Framer Motion。
- 本轮不改变音频代理、播放后端、统计接口或数据返回结构。

## 3. 设计目标

### 3.1 可用性目标

- 任何皮肤、任何明暗模式下，播放进度均可辨认、可点击、可拖动扩展。
- 普通歌词与全屏歌词都不存在文字和操作按钮重叠。
- 全屏模式只有两个可见窗口操作按钮，不显示重复入口。
- 返回首页时保留已有内容与滚动位置，不重新出现首屏加载占位。
- 显式点击“刷新推荐”时才强制重新请求首页推荐。

### 3.2 视觉目标

- 不看设置名称，仅看截图即可判断当前是 Aurora 还是 Newsprint。
- 首页推荐播放器和底部播放条成为界面视觉锚点，不再显得空荡。
- 两套皮肤在布局、组件形状、信息密度、字体层级和交互反馈上均有明显区别。
- 深色模式不是整体降低透明度，而是重新定义表面、文字、轨道和交互状态的对比关系。
- 不看静态截图时，两套皮肤的运动节奏也必须可以被区分。

### 3.3 性能目标

- 返回已访问首页不触发三组首页数据请求。
- 首页切换不销毁已缓存的 HomeView 实例。
- 页面切换只动画 `opacity` 与 `transform`，不动画大面积 `width`、`height` 或滤镜。
- 歌词自动跟随在新行到达时只存在一个滚动行为，旧滚动可被新状态覆盖。
- 模糊、颗粒和阴影均有明暗模式与低性能降级规则。
- `prefers-reduced-motion: reduce` 下立即到达最终状态。

## 4. 总体架构

采用“共享无头控制器 + 独立皮肤展示组件”的结构。

### 4.1 共享层

共享层负责业务，不包含皮肤特定 DOM：

- 当前曲目、播放状态、音质、循环模式、音量、进度。
- 首页推荐数据、加载状态、错误状态和显式刷新。
- 导航历史、视图身份、缓存策略和每视图滚动位置。
- 歌词解析、当前行、自动跟随状态和全屏状态。
- Tauri 窗口最小化与关闭行为。

### 4.2 展示层

高识别度页面使用真正独立的 Vue 组件：

- `AuroraShell` / `NewsprintShell`
- `AuroraHome` / `NewsprintHome`
- `AuroraPlayerBar` / `NewsprintPlayerBar`
- `AuroraLyricStage` / `NewsprintLyricStage`

这些组件消费相同的只读 view model，并通过明确事件调用共享控制器。禁止在两个皮肤组件中复制 API 请求、播放队列或窗口控制逻辑。

### 4.3 皮肤选择

`themeStore.skinId` 只负责选择展示组件和对应 token 集，不再承担“让同一个模板看起来有一点不同”的责任。

切换皮肤时：

1. 播放与页面数据保持不变。
2. 当前页面、搜索词、播放进度和歌词行保持不变。
3. 只更换 shell 与页面展示组件。
4. 使用短促交叉淡化，不重新请求数据。

### 4.4 次级页面与组件原语

搜索、歌单、统计、历史、设置和均衡器继续共享业务页面，避免复制 API 与状态逻辑；但它们不能继续直接依赖一套全局 `.card`/`.page-head` 外观。两套界面分别提供导航、页面标题、列表行、卡片、按钮、输入框、空状态和弹层原语，次级页面只组合这些原语。

因此，“两套独立界面”的边界是：Shell、首页、播放器和歌词拥有独立模板；次级页面拥有共享业务结构和独立皮肤原语。任何只改颜色、但仍暴露另一皮肤形状语言的组件都不算完成。

## 5. 首页保活与数据流

### 5.1 稳定视图身份

当前 `viewTransitionVersion` 同时承担动画 key 和组件身份，导致每次导航都产生新实例。重构后分离两个概念：

- `transitionKey`：只用于进出场动画。
- `cacheKey`：标识可复用的页面实例；首页固定为 `home`，歌单使用 playlist id，搜索使用已提交查询。

视图宿主改为动态组件，并以 `KeepAlive` 缓存 HomeView。组件切换仍有动画，但缓存实例不会因动画 key 变化而失效。

### 5.2 首页数据控制器

将首页三组请求从展示组件中抽到共享 `useHomeFeed`/store：

- 第一次进入：并发请求每日歌曲、推荐歌单和最新歌单。
- 返回首页：直接使用内存数据，不请求、不清空。
- 显式刷新：保留旧数据，显示局部刷新状态，请求成功后原位替换。
- 刷新失败：旧数据继续显示，并给出非阻塞错误提示。
- 同一时刻只允许一轮首页请求；重复点击复用进行中的 Promise。

### 5.3 首屏稳定性

- 已有数据时不得重新显示全页 spinner。
- 图片使用稳定尺寸和 `aspect-ratio`，避免加载后布局跳动。
- 封面失败使用与当前皮肤匹配的占位，不卸载内容容器。
- 首页滚动位置按皮肤与视图分别保存，返回后恢复。

## 6. Aurora 独立界面

Aurora 定位为现代、沉浸、轻量的桌面音乐播放器。参考 Mineradio“音乐是视觉舞台”的核心思路，但控制视觉复杂度。

### 6.1 Shell

- 标题栏与顶部导航融为一个连续表面，不使用横线。
- 左侧导航更窄，图标与当前状态使用清晰实色反馈。
- 顶部搜索是主要命令入口，账户和工具按钮收敛到右侧。
- 使用无衬线字体、柔和圆角、低层级阴影和清晰的表面高差。
- 深色模式使用深灰层次，不使用大面积低透明文字。

### 6.2 首页推荐播放器

红框区域改为真实内容驱动的“视觉舞台”：

- 使用每日推荐第一首或当前播放曲目的真实封面作为主视觉。
- 清晰显示歌曲名、歌手、推荐来源、播放按钮和队列数量。
- 提供紧凑的推荐轨道预览，不再使用大面积空白和装饰 SVG 唱片。
- 未播放时展示今日推荐；播放后自然切换为正在播放舞台。
- 视觉舞台占据首屏主要面积，但始终保留可辨认的完整封面。

不在第一阶段加入粒子、WebGL、3D 或音频频谱。它们会增加 GPU/音频图复杂度，且无法解决当前信息密度和重复加载问题。

### 6.3 Aurora 底部播放器

- 采用一体化控制台，而非三个彼此疏远的列。
- 左侧为清晰封面与元数据，中间为主要播放操作，右侧为质量、队列、歌词与音量。
- 进度条横跨控制台主要宽度，位于播放按钮下方或与元数据对齐。
- 当前进度使用 Aurora accent，未播放轨道在深色模式下保持明确可见。
- hover、pressed、loading 使用细微缩放、颜色和旋转反馈，不使用大幅位移。

### 6.4 Aurora 动效性格：柔软果冻

Aurora 的“果冻感”来自短距离形变、快速跟手与柔和回弹，不是让整个页面晃动：

- 大型视觉舞台进入时从 `scale(0.96)`、`translateY(14px)` 和低透明度快速收拢到稳定状态。
- 主播放按钮按下时压缩至约 0.92，释放时使用短弹性 ease 回到 1。
- 进度滑块拖动时轻微横向拉伸、纵向压缩；释放时立即回弹，不延迟 seek。
- 当前导航背景使用可移动的选择指示层，切换时像软质胶囊滑向新位置。
- 封面切换先等待新图可用，再执行 180-260ms 交叉淡化与轻微缩放。
- 推荐卡片 hover 只抬升 4-6px，并带柔和阴影扩散；离开时快速归位。
- 播放状态允许视觉舞台进行极慢、极小幅的呼吸缩放；暂停、窗口失焦或 reduced-motion 时停止。

Aurora 可使用 `back.out` 与低强度 `elastic.out`，但弹性动画只用于主播放按钮、进度滑块和视觉舞台，不传播到正文、歌词和列表滚动。

## 7. Newsprint 独立界面

Newsprint 定位为编辑版、文化刊物和广播台风格。复古感来自排版、密度和图像处理，而不是重复双线与满屏边框。

### 7.1 Shell

- 标题栏、侧栏与内容使用连续纸面，不使用顶部横线。
- 标题使用衬线体，功能标签和数字使用紧凑无衬线或等宽字体。
- 导航采用编辑目录式编号、缩进和字重变化，不使用 Aurora 的胶囊与玻璃按钮。
- 明亮模式使用暖纸色；深色模式使用深墨纸面与高对比文字，不简单降低整体 opacity。

### 7.2 首页推荐播放器

- 红框区域改为“头版主稿”式推荐模块。
- 大幅真实封面与主推荐标题形成非对称版式。
- 同一区域呈现前三首推荐、编辑短句与直接播放入口。
- 使用留白、字级、编号和块面建立层次，不再绘制装饰唱片。
- 图片可使用轻微网点/降饱和处理，但鼠标悬停或播放时恢复清晰色彩。

### 7.3 Newsprint 底部播放器

- 采用广播台播出条结构：封面与节目名、运输控制、进度/时间、辅助控制形成紧凑节奏。
- 不复用 Aurora 的圆角容器和悬浮按钮。
- 进度使用实线与明确滑块，不使用当前深色模式下难以辨认的点线轨道。
- 深色 Newsprint 依靠墨黑、灰白和单一强调色形成层级。

### 7.4 Newsprint 动效性格：排版与印刷

Newsprint 也需要明显升级动效，但保持编辑版面的克制：

- 页面区块以 8-12px 的短距离上移和 `power3.out` 淡入，不使用弹簧。
- 推荐列表按 20-35ms 小间隔依次显现，形成“排版落版”的节奏。
- 按钮按下使用 1-2px 位移与阴影收紧，模拟铅字压印，而不是果冻缩放。
- 封面 hover 通过彩色覆盖层淡出恢复原色，避免持续动画昂贵的滤镜。
- 当前播放行使用背景块和字重变化平滑切换，不使用发光与大幅缩放。
- 页面切换比 Aurora 更快、更干脆，结束后完全静止。

Newsprint 的运动应让用户感到“内容被排好并印下来”，而不是现代界面的另一套 easing。

## 8. 进度条系统

新增语义 token：

- `--progress-track`
- `--progress-buffered`
- `--progress-fill`
- `--progress-thumb-fill`
- `--progress-thumb-ring`
- `--progress-time`

规则：

- 轨道与相邻背景至少形成 3:1 的非文本对比。
- 可见线条可保持 3px 左右，但实际点击区域高度不少于 16px。
- 滑块默认可见，hover/focus 时增大，不依赖鼠标悬停才出现。
- 键盘方向键支持小步 seek，Home/End 支持首尾定位。
- 暗色 token 单独定义，不从浅色 token 透明叠加推导。
- Aurora 与 Newsprint 使用不同形态，但共享 seek 计算与无障碍语义。

## 9. 顶部融合与窗口控制

删除所有装饰性横线来源：

- `.titlebar` 的 `border-bottom`
- `.titlebar::after`
- `.page-head` 的双规则线与重复伪元素
- 仅用于模拟报纸分隔、但不承载信息层级的横线

分区改用背景层、间距、字级和局部阴影区分。Newsprint 也遵守“无顶部横线”要求。

普通模式保留最小化、最大化与关闭。歌词全屏模式改为专用 `FullscreenWindowControls`：

- 只显示最小化。
- 只显示退出全屏。
- 隐藏最大化、关闭、Logo、Working Set 与普通“全屏”按钮。
- 两个按钮位于同一右上操作区，保持可拖动安全区域。
- Esc 仍退出歌词全屏。

## 10. 歌词普通模式与全屏模式

### 10.1 普通模式

- 歌词区采用三行网格：元信息/歌词视口/跟随操作区。
- “回到当前行”位于固定高度的底部操作区。
- 自动跟随开启时保留操作区高度但隐藏按钮，避免歌词区域跳动。
- 按钮不可覆盖歌词，歌词最后一行保留足够底部 padding。

### 10.2 全屏模式

- 使用独立的全屏舞台模板，不在普通页面模板上继续叠加 fixed 按钮。
- 左侧封面和右侧歌词按窗口尺寸自适应；小窗口退化为上下布局。
- 封面始终保持正方形和完整可见。
- 当前歌词保持最高对比，邻近歌词分三级弱化，禁止整页低透明。
- 全屏进入/退出只使用容器淡化和封面轻微缩放。
- 全屏顶部不显示普通页面标题、日期、同步状态和重复全屏按钮。

## 11. Motion 与交互原则

继续以 `motion.ts` 作为 GSAP 边界，并增加按皮肤选择的 `MotionProfile`。共享业务组件不得直接散落 GSAP 参数；展示组件通过统一 helper 使用对应 profile。

### 11.1 共享规则

- 页面离开：140-180ms，快速淡出，旧 tween 在新导航开始时被 kill。
- 皮肤切换：160ms 淡出，切换展示组件，220-280ms 淡入；数据层不重建。
- 封面切换：只在新图完成解码后交叉淡化。
- 首页返回：缓存视图直接恢复，不重新播放整套首屏入场动画。
- 歌词滚动与按钮出现不得同时对同一元素写 transform。
- 连续动画只允许作用于合成层的 `transform`/`opacity`，窗口失焦或页面隐藏后暂停。
- 用户交互反馈必须在 100ms 内开始，禁止为了等待动画延迟播放、seek 或导航。

### 11.2 Aurora Profile

- 页面进入：260-360ms，`expo.out` 或 `back.out(1.25-1.5)`。
- 主控件释放：380-520ms 的低强度 `elastic.out`。
- 列表 stagger：30-45ms，最多前 8 项；更多项目直接显示。
- 视觉舞台呼吸：仅播放中启用，周期不短于 5 秒，缩放幅度不超过 1.015。

### 11.3 Newsprint Profile

- 页面进入：180-260ms，`power3.out`。
- 按钮按压/释放：80-140ms，`power2.out`，无弹性过冲。
- 列表 stagger：20-35ms，最多前 10 项。
- 页面稳定后无环境循环动画。

### 11.4 性能与可取消性

- 每个 helper 返回可取消 tween/timeline，视图离开和组件卸载时统一清理。
- 同一元素的新动画开始前执行 `killTweensOf`，避免快速导航时叠加。
- 禁止对大面积 `filter`、`backdrop-filter`、`box-shadow` 和布局尺寸做逐帧 tween。
- 通过 CSS 变量或 GSAP context 将动画限定在当前皮肤根节点。
- 动效验收同时检查“可见、跟手、结束稳定”，不能只检查动画是否被调用。

Awwwards GSAP 与 Sites of the Day 只作为动效节奏和完成度参考，不照搬营销站滚动、视差或 WebGL。参考：

- https://www.awwwards.com/websites/gsap/
- https://www.awwwards.com/websites/sites_of_the_day/
- https://mineradio.cn/
- https://github.com/XxHuberrr/Mineradio

## 12. 错误、加载与降级

- 初次首页加载：各 section 使用保持尺寸的骨架，不显示全页空白。
- 返回首页：显示缓存内容，不显示骨架。
- 手动刷新：旧内容保留，刷新按钮显示进行中状态。
- 单个 section 失败：只影响该 section，其他数据不清空。
- 封面失败：固定比例占位，布局不移动。
- 低性能或 reduced-motion：关闭大面积模糊、颗粒动画与非必要过渡。
- 皮肤展示组件异常不得影响共享播放状态。

## 13. 测试与验收矩阵

### 13.1 单元/组件测试

- 返回首页不会再次调用三组首页 API。
- 手动刷新只启动一轮请求，旧数据在请求期间保持可见。
- HomeView 在导航切换中保持缓存实例。
- 两套皮肤渲染不同的 Shell、Home、PlayerBar 和 LyricStage 组件。
- 两套皮肤分别选择 Aurora 与 Newsprint MotionProfile。
- 次级页面使用当前皮肤的标题、列表、卡片、按钮、输入与弹层原语，不直接复用另一皮肤形状。
- 皮肤切换不改变当前曲目、时间、队列或当前页面。
- 深色模式进度条使用专用暗色 token。
- 歌词跟随按钮位于底部操作区，并在点击后恢复跟随。
- 全屏模式恰好显示最小化和退出全屏两个窗口操作。
- 全屏退出支持按钮和 Esc。
- 快速重复导航不会在同一元素留下多个活动 tween。
- reduced-motion、窗口失焦和页面隐藏会停止环境循环动画。

### 13.2 视觉测试

覆盖以下矩阵：

- Aurora light / Aurora dark
- Newsprint light / Newsprint dark
- 1280x720、1440x900、1920x1080/1200
- 首页、普通歌词、全屏歌词
- 空数据、加载中、正常数据、长歌名、无封面

验收截图中不得出现：

- 顶部装饰横线。
- 进度条不可见。
- 歌词按钮覆盖正文。
- 全屏重复按钮。
- 首页推荐播放器大片无意义空白。
- 两套皮肤仅颜色不同、结构相同。

### 13.3 性能验证

- 浏览器开发模式记录首页 -> 其他页面 -> 首页流程的网络调用，返回时首页 API 调用数为 0。
- 记录页面切换和歌词自动跟随帧时间，确认无持续长任务和重复平滑滚动。
- 分别录制 Aurora 果冻回弹与 Newsprint 排版入场，确认交互反馈在 100ms 内开始。
- 检查大面积 `backdrop-filter`、阴影和颗粒层在深色模式下的合成开销。
- 前端完整 Vitest、`vue-tsc --noEmit` 必须通过。

## 14. 实施边界与顺序

实施分为可独立验收的六个阶段：

1. 稳定视图身份、KeepAlive 与首页数据控制器。
2. 语义视觉 token、双 MotionProfile、进度条和顶部横线清理。
3. 独立 Aurora/Newsprint Shell 与首页推荐播放器。
4. 独立 Aurora/Newsprint 底部播放器。
5. 独立歌词舞台、底部跟随按钮和精简全屏控制。
6. 视觉矩阵、性能测量、全量回归与文档收口。

每一阶段先写失败测试，再完成最小实现，验证后独立提交。不得把所有模板一次性重写后才补测试。

## 15. 非目标

- 不更换 Vue、Tauri、GSAP 或播放器后端。
- 不新增音频粒子分析、WebGL、3D 歌单架或视频背景。
- 不修改 AudioProxy、播放 URL、EQ、统计数据库和登录协议。
- 不复制 Mineradio 的素材、品牌、源码或完整交互。
- 不在本轮新增移动端产品形态；只保证桌面窗口缩放下可用。

## 16. 完成定义

同时满足以下条件才算完成：

- 两套独立展示组件已落地，并共享同一业务控制器。
- 返回首页无重新拉取、无先空后填、保留滚动与已有数据。
- 红框推荐播放器和底部播放条在两套界面中都有独立设计。
- 四种皮肤/明暗组合的进度条均清晰可用。
- 顶部装饰横线全部消失。
- 歌词跟随按钮不遮挡正文。
- 全屏只出现最小化和退出全屏。
- 自动化测试、类型检查、视觉检查和性能检查全部通过。
