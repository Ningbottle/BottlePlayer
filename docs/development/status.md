# 当前状态

截至 2026-10-18，Qt 应用仍是开发预览版。源码包含搜索、账户、歌单、历史、统计、设置、均衡器、设备选择、外观和沉浸播放；“有页面/有实现”不等同于所有真实服务场景已验收。

## 已有回归覆盖

- 账户、播放会话、曲库、统计和设置档案契约。
- 推荐列表的过期结果、连续队列推进、取消和失败保留。
- 推荐专辑独立来源、每日歌曲展开收起、侧栏宽度保存和窗口内沉浸歌词。
- PCM 输出格式、设备路由、均衡器及暂停恢复。
- 原生身份提交、请求取消/截止时间、HTTP 预算及数据库生命周期。
- Native 的 Qt 依赖负例、2000 首队列投影与通知、600 行歌词时钟读取，以及清空/补齐元数据的缓存一致性。

2026-10-17 的本地现场验证覆盖了连接耳机的实际输出、在线歌曲及连续推荐前两首。该结果只代表当时环境，不能推断所有设备、歌曲或上游接口稳定。

## 性能优化顺序

第一批收敛已经确认的重复工作：歌词组件只在内容改变时读取整首歌词，填色时读取当前行缓存；播放列表投影按内容更新，索引、红心开关与请求等待独立通知；Native 的独立构建和依赖守卫进入自动验证。回归用读取次数和信号次数约束行为，2000 首 getter 微基准只衡量属性读取，不推断帧率。

后续按以下顺序推进，每批先记录耗时和次数，再实现并比较相同场景：

1. **持久化与诊断**：测量 2000 首队列保存、侧栏拖动、日志轮转在 GUI 线程的耗时及锁等待。合并写入需要同时处理退出、导入和导出；诊断异步化需要有界缓冲和关机收尾。验收包括最后一次修改落盘、导入不被旧任务覆盖，以及日志不丢失关键错误。
2. **音频控制开销**：测量音量/均衡器修改是否反复枚举设备或重新协商格式，再拆分音量控制与格式配置。验收仍须包含实际耳机输出、设备切换、暂停、恢复和切歌。
3. **大列表增量更新**：测量队列、曲库和历史的过滤、转换与 QML 模型重建。仅对证实需要的列表引入 `QAbstractListModel`，后台结果回到 GUI 线程后增量提交，避免同时维护两个可写真值。
4. **渲染与封面**：先使用 QML Profiler 区分绑定、布局、绘制与图片解码。现有封面已异步加载，色彩提取也在后台；出现本地内嵌封面功能或确认瓶颈后再评估专用图片提供器。频谱渲染按实际采样/绘制路径决定，不预先增加一套线程或环形缓冲。

每批记录播放与暂停、长歌词、2000 首列表、窗口缩放的相同负载，比较 GUI 耗时分布、绑定/转换次数和内存峰值。没有场景测量时不承诺统一的 2ms 上限或“零拷贝”。线程所有权和状态归属见 [总体架构](../architecture/overview.md)。

## 每次候选交付仍需验收

- 无声、设备重连、音质切换失败后的恢复，以及不同驱动/多输出设备。
- 真实账户的扫码、换号、权限变化、歌单写入和网络失败；写操作只在用户授权的账号执行。
- 上游返回变化、不可播放内容、更新渠道和完整便携包启动。
- 长时间播放、缩放、多屏/DPI、外观切换和性能表现。

不按主观百分比判定迁移完成。候选构建应记录提交、运行库、测试结果和实际未验证范围；具体命令见 [构建与验证](build-and-test.md)。
