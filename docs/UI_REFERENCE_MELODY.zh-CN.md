# Melody 参考界面设计规格

本文记录用户提供的两张 Melody 风格参考图，并把它们拆成 BottleMusic 首版原生 UI 规格。后续 `EchoWin32` 实现应以本文为准。

## 参考图

参考图 A：播放详情页。

- 左侧固定导航。
- 顶部返回、前进、搜索、用户头像和窗口按钮。
- 主区域左侧是专辑封面和黑胶唱片视觉。
- 主区域中间是歌词。
- 右侧是播放队列。
- 底部是持久播放栏。

参考图 B：首页。

- 左侧固定导航。
- 顶部返回、前进、搜索、用户头像和窗口按钮。
- 主区域左侧是问候语、今日推荐横幅、推荐卡片、推荐歌单。
- 主区域右侧是最近播放和艺人推荐。
- 底部是持久播放栏。

如后续需要文件化保存截图，建议放入 `docs/reference-images/`，并在本文补充文件路径。

## 视觉原则

- 浅色主背景，整体温和。
- 蓝色作为主强调色，用于当前导航、播放按钮、进度、当前歌词。
- 卡片圆角克制，建议 8px。
- 列表分割线轻，不能喧宾夺主。
- 图片是视觉重心，文字和控件为图片让位。
- 信息密度接近参考图，不做过度留白。

## 全局布局

参考尺寸为 1600 x 1060。

- 侧边栏宽度约 178px。
- 顶部区域高度约 86px。
- 底部播放栏高度约 96px。
- 内容区位于顶部和底部之间。
- 窗口圆角和阴影由系统能力或自绘策略决定，但不应牺牲性能。
- 最小可用窗口为 900x640；低于常规桌面宽度时进入紧凑布局。
- 最小尺寸指客户区尺寸，不是包含标题栏和边框的外窗口尺寸。
- 原生窗口必须启用 DPI 感知，避免系统位图缩放造成文字发糊。
- 紧凑布局优先保证当前歌曲、播放/暂停、上一首、下一首、进度条、队列和歌词入口可读。
- 紧凑布局可以隐藏音量条、随机/循环等次级控制，但不能让按钮重叠。
- 首页紧凑布局只保留问候语、今日推荐横幅和一行推荐卡片；最近播放、推荐歌单大面板和艺人推荐不再硬塞进小窗口。
- 首页内容必须裁剪在内容区内，不能画到底部播放栏上方或下面。
- 首页高度不足时推荐卡片整块隐藏，不能把真实封面压成横条图。
- 桌面宽度下即使高度较低，也要保留最近播放等功能入口；不能只按高度把页面退化成极简模式。
- 推荐卡片使用固定比例和最大宽度，不随超宽窗口无限拉伸。
- 侧边栏列表只绘制到播放栏上方，不能穿到播放器底栏下面。
- 播放详情页在宽度不足时隐藏右侧队列，把空间让给歌词；队列入口仍保留在底部播放栏。

## 侧边栏

内容：

- 品牌区：音符图标 + BottleMusic。
- 主导航：首页、发现、电台、视频。
- 我的音乐：歌曲、专辑、歌手、播放列表、收藏夹、最近播放、下载管理。
- 播放列表：用户播放列表快捷入口。
- 底部设置入口。

规则：

- 当前项使用浅色选中底和蓝色图标/文字。
- 行高固定，hover 不改变布局尺寸。
- 播放列表缩略图使用 `EchoImage` 加载，尺寸固定。

## 顶部栏

内容：

- 返回按钮。
- 前进按钮。
- 搜索框。
- 用户头像。
- Windows 窗口按钮区域。

规则：

- 搜索框居左，宽度在桌面尺寸下约 600px。
- 搜索框不阻塞 UI，输入建议通过异步请求。
- 顶部栏不承载大量业务状态。

## 首页

区域：

- 问候语。
- 今日推荐横幅。
- 为你推荐卡片行。
- 推荐歌单卡片行。
- 最近播放列表。
- 艺人推荐。

今日推荐横幅：

- 使用大图背景。
- 左侧文字叠加。
- 有主要播放按钮。
- 右下角可有轮播点。
- 图片加载失败显示柔和占位，不撑坏布局。

推荐卡片：

- 固定图片比例。
- 图片下方显示标题和歌曲数量。
- 右下角叠加圆形播放按钮。
- 列表水平排列，宽度不足时减少可见数量或横向滚动。

最近播放：

- 行内显示封面、歌曲名、歌手、专辑、时长、更多按钮。
- 列表高度固定，超出走虚拟化。
- 不为每行长期持有复杂文本布局对象。

艺人推荐：

- 圆形头像。
- 艺人名、粉丝数、关注按钮。
- 头像通过 `EchoImage` 管理。

## 播放详情页

区域：

- 顶部 tab：正在播放、歌词。
- 左侧封面和黑胶唱片。
- 歌曲信息和局部进度。
- 中间歌词。
- 右侧播放队列。
- 底部播放栏。

封面：

- 封面大图固定正方形。
- 右侧露出黑胶视觉。
- 黑胶可以先用轻量矢量绘制，不需要图片资源。
- 播放中可逐步旋转，但首版可先静态。

歌词：

- 当前行使用蓝色和更大字号。
- 非当前行使用灰色。
- 歌词居中排列。
- 支持按播放进度定位当前行。
- 手动滚动时暂停自动跟随，显示回到当前行入口。

播放队列：

- 显示当前播放、历史记录 tab。
- 当前播放行有蓝色强调和播放中小图标。
- 支持清空和更多菜单入口。
- 队列列表必须虚拟化。

## 底部播放栏

内容：

- 当前封面。
- 歌曲名和歌手。
- 收藏按钮。
- 播放模式、上一首、播放/暂停、下一首、循环。
- 进度条和时间。
- 音量。
- 队列按钮。
- 歌词按钮。

规则：

- 始终固定在底部。
- 所有按钮命中区域固定。
- 进度条拖动不触发主布局变化。
- 播放状态变化不能导致播放栏跳动。
- 900px 宽时进度条可读宽度不少于 220px。
- 1180px 以下隐藏音量条，1120px 以下隐藏随机/循环，避免控件挤在一起。
- 播放、暂停、上一首、下一首优先使用 Direct2D 矢量绘制，不依赖字体符号。
- “词”按钮和队列按钮必须是明确入口，点击后进入播放/歌词页。

## 首版实现策略

第一阶段只要求两张参考图覆盖的核心体验：

1. 首页静态布局 + 假数据。
2. 播放详情页静态布局 + 假数据。
3. 底部播放栏共享。
4. 图片加载走 `EchoImage`，没有图片时用占位。
5. 列表绘制使用虚拟化基础设施。
6. 后续再绑定真实 `IBackendFacade` 和 `IPlaybackController`。
