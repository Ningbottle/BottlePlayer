# BottleMusic 实现规则

## 总规则

- 默认用中文写项目文档和沟通说明。
- C++ 标识符使用英文。
- 新代码优先放入对应 Module。
- 修改前确认依赖方向。
- 新功能必须说明内存影响。
- UI 和后端通过 typed Interface 协作。

## UI 规则

- UI 线程不做网络请求。
- UI 线程不做 SQLite 查询。
- UI 线程不做图片解码。
- UI 不直接调用 Media Foundation。
- UI 只持有当前页面 ViewModel 和可见区域数据。
- 所有列表都要准备虚拟化，尤其歌曲、歌单、搜索结果、队列、评论。
- 控件状态变化不能导致布局跳动。
- 文本必须适配中文、英文、长歌名和长艺人名。

## 图片规则

- 所有图片加载走 `EchoImage`。
- 不允许页面自己持有无限 Direct2D bitmap。
- 图片请求必须可取消。
- 不可见列表项的图片应能释放。
- 图片缓存必须有内存上限和磁盘上限。

## 后端规则

- 酷狗接口细节集中在 `EchoCore`。
- Authorization、dfid、mid、uuid、guid、mac、token 不泄漏到 UI。
- 兼容 JSON 和 typed DTO 分开。
- 大响应不要长期保留原始 JSON。
- 分页接口不要一次性拉取全部历史。

## 播放规则

- `EchoPlayback` 只暴露状态和命令。
- UI 监听播放状态 snapshot，不直接持有 Media Foundation 对象。
- 播放失败必须有明确错误。
- 切歌时释放旧播放对象。
- 不整曲解码缓存。

## 异步规则

- 所有后台任务必须可追踪。
- 页面销毁或切换时取消无用任务。
- 关闭程序时等待或取消后台任务。
- 后台错误通过事件队列回到 UI。

## 诊断规则

- 每个阶段保留可读日志。
- 内存快照应包含进程内存、图片缓存、队列长度、当前页面、播放状态。
- 性能问题先诊断再改。
- 不用猜测替代测量。

## 兼容服务规则

- `EchoCompatServer` 只用于开发调试。
- 不把兼容 HTTP 当作最终 UI 内部协议。
- 未迁移接口返回稳定错误，不伪造成功。
- 兼容响应只保证旧前端需要的字段，不扩大成最终模型。

## 依赖规则

- 引入依赖前写清楚理由。
- 优先 Windows 原生能力。
- 优先小依赖。
- 大依赖必须说明内存、体积和替代方案。
- 首版不默认引入 FFmpeg、libmpv、Chromium、WebView2。
