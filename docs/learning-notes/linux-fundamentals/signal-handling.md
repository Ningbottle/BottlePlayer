# 2. 捕捉函数：
我们之前说过handler表格里面有三种处理方式 ：
1. 默认处理方式：宏是`SIG_DFL`，即信号原本要做什么，就做什么。
2. 忽略的处理方式：宏是`SIG_IGN`，就是忽略信号，这也是一种处理信号的方式。
3. 第三种就是自定义，通过回调函数告诉信号怎么做。

## 2-1 首先来看看`SIG_IGN`的方式：
我们顺便回顾一下，我们之前学习到`signal`函数，代码如下：
```cpp
#include <iostream>
#include <signal.h>

int main()
{
    for (int i = 1; i < 32; i++)
    {
        if (i == SIGKILL || i == SIGSTOP)
        {
            std::cout << "跳过9号和19号信号" << std::endl;
            continue;
        }
        if (signal(i, SIG_IGN) == SIG_ERR)
            // 有些信号可能不允许设置忽略（如 SIGSEGV 等），这里只是简单打印错误
            perror("signal");
        else
            printf("信号 %d 已被设置为忽略\n", i);
    }

    for(int i = 1; i < 32; i++)
    {
        if (i == SIGKILL || i == SIGSTOP)
            continue;
        sleep(1);
        std::cout << "正在发送" << i << "号信号" << std::endl;
        raise(i);
    }
    return 0;
}
```
我们可以看到`signal`这个函数是可以把信号设置位忽略的。最后，这个结果是：
![image.png](https://cdn.jsdelivr.net/gh/Ningbottle/blog-images@main/img/20260307154639734.png)
我们可以看到，发送这些信号(除了9号和19号信号) 我们全部处理为忽略。


## 2-2 认识`sigaction`函数（Signal Action）
**在现代 Linux 编程中，强烈建议一律使用 `sigaction`。**（事实上，现代 Linux 的 glibc 库里，`signal()` 底层通常也是偷偷调用 `sigaction` 来实现的）。
![image.png](https://cdn.jsdelivr.net/gh/Ningbottle/blog-images@main/img/20260307155035411.png)
看到这三个参数，其实大部分，我们都是认识的：
1. signum 不用多说，就是传入要改变的信号。
2. 第二个，不在传入一个简单的函数，而是可以支持通过改变结构体来传入，这是我们后面需要详细讲的。
3. oldact，这个是和第二个一样的结构体，一般带有old都是输出型参数，这个保存老操作函数的结构体。防止之前的操作是需要后面使用的。


我们来详细介绍这个结构体，是干什么的，长什么样。
![image.png|651](https://cdn.jsdelivr.net/gh/Ningbottle/blog-images@main/img/20260307160825180.png)
这个就是自带的结构体，我们可以来分析一下：
1. 第一个就是处理的函数，`void (*)(int)`，几乎和signal 函数是一样的。
2. 第二个就是高级的处理函数：能带出海量信息
3. 第三个就是掩码，执行处理函数时，临时屏蔽哪些信号（保护现场），类型是`sigset_t`（信号集/位图）。处理函数运行期间，这些信号会被临时**阻塞**（进入未决状态），函数执行完后，内核会自动解除阻塞。

在这篇文章，我们不做详细的介绍，这里只是初步的认识一下，来看一个简单的例子：
```cpp
void handler(int signo, siginfo_t *info, void *context) {
    std::cout << "捕捉到信号: " << signo << std::endl;
    // 高级的可以带出好多消息
    std::cout << "发送者 PID: " << info->si_pid << std::endl;
    std::cout << "正在处理中，此时我屏蔽了 SIGQUIT (Ctrl+\\)..." << std::endl;
    
    sleep(5); 
    std::cout << "处理完毕！" << std::endl;
}

int main() {
    struct sigaction act, old_act;

    // 2. 初始化 sa_mask (临时护盾)
    // 我们希望在处理 SIGINT (Ctrl+C) 时，顺便把 SIGQUIT (Ctrl+\) 也给挡住
    sigemptyset(&act.sa_mask);//初始化
    sigaddset(&act.sa_mask, SIGQUIT);

    // 3. 必须设置 SA_SIGINFO，否则内核只看 sa_handler，不看 sa_sigaction
    act.sa_flags = SA_SIGINFO;

    // 4. 设置 sa_sigaction (高级收货员)
    act.sa_sigaction = handler;

    // 监控 SIGINT，旧动作存到 old_act
    if (sigaction(SIGINT, &act, &old_act) == -1) {
        perror("sigaction error");
        return 1;
    }

    std::cout << "我的 PID 是: " << getpid() << "，我在等 Ctrl+C..." << std::endl;

    while (true) {
        pause(); // 让进程挂起，等待信号
    }

    return 0;
}

```
![image.png](https://cdn.jsdelivr.net/gh/Ningbottle/blog-images@main/img/20260307162816648.png)

处理结果是我们在这个窗口发送信号，可以捕捉信号，发送者是谁，而且在这五秒钟我们还屏蔽了`SIGQUIT`，在这 5 秒内按 `Ctrl+\`，你会发现没反应（被 `sa_mask` 挡住了）。结果正如我们分析的那样。

这个就是利用了第二个参数来完成对信号的自定义，这次我们开始换第一个参数来完成测试：
```cpp
void handler(int signum)
{
    std::cout << "我接受到了一个信号:" << signum << std::endl;
    exit(1);//接受一个信号就结束
}

int main()
{
    struct sigaction old_act,act;
    act.sa_handler = handler;
    // 注意下面的必须要给出地址：
    int n = sigaction(2,&act,&old_act);
    if(n == -1)
        perror("sigaction error");
    while(true)
    { 
        std::cout << "你可以输入二号信号" << std::endl;
        sleep(2);
    }
}
```

## 3-1理解硬件中断：
当我们之前写c++代码的时候，我们使用了`cin`或者`scanf`的时候，我们不敲下字母，其中进程是不会继续运行的，这是键盘没有反应，导致这个进程阻塞。
而我们当我们敲下并回车的时候，进程立马继续运行，直至完成运行这个进程。
>**硬件中断（Hardware Interrupt）** 是由计算机外部硬件设备主动向 CPU 发出的"紧急通知"机制。它是硬件与 CPU 之间的**异步通信方式**——CPU 不需要主动询问设备状态，当设备准备好数据或发生重要事件时，会"打断" CPU 当前的工作，迫使 CPU 立即处理该事件。

当我们敲下键盘，确实会发一次**硬件中断**；而正是这个中断，最终导致了你那处于阻塞状态的 C++ 进程**继续运行**。
为了更好的理解操作系统的内部的问题和运行机制，我们通过谷歌的nano banana 2生成一张图片，**<font color="#ccc1d9">虽然图片种的中的中文文字可能会出现一些问题</font>**：
![image.png](https://cdn.jsdelivr.net/gh/Ningbottle/blog-images@main/img/20260307190009338.png)

我们先来梳理一边刚刚的过程：
1. 键盘内部的芯片会检测到按键动作，并通过主板向 CPU 发送一个电信号。这就是**硬件中断请求（IRQ）**。
2. CPU 保存现场，切换到**内核态**，查 IDT 表，执行**键盘中断处理程序（ISR）。**这就回到了我们刚才画的那张图：CPU 收到中断信号，立刻放下手里正在干的其他活，保存现场，然后跳转到操作系统内核中对应的**键盘中断服务程序（ISR）**。
3.  **关键操作**：检查"等待队列" → 发现有你的进程正在等待输入，**唤醒进程**：将你的进程状态从 **阻塞** 改为 **就绪（Ready）**，移回"就绪队列" 中断处理结束，执行 `IRET` 准备返回

大致是这个意思：我们再来详细的解释一下这个图片：
1. 首先是外部设备:这里可以暂时理解成为信号产生，发送一个电信号，通过中断控制器来完成对电信号进行转换。**电信号 -> 中断号：** 键盘、鼠标等硬件产生的是物理上的**电信号（IRQ 请求）**。中断控制器接收到这些电信号，判断优先级后，把它翻译成一个 CPU 能看懂的数字，也就是 **中断号（Interrupt Vector/Number）**，然后发送给 CPU。
2. 接下来就是中断向量表了，这个我的理解就是一个紧急事故通知书。写了当中断号来了应该怎么办？在之前我一直以为中断向量表里面是函数，其实不是的：**向量表 -> 提供方法：** 这里稍微精确一点：向量表里存放的**不是方法本身的代码**，而是存放着**方法的内存地址（指针）**。CPU 查表拿到这个地址后，就会把程序计数器（PC寄存器）指向这个地址，从而跳过去执行真正的处理代码，也就是**中断服务程序（ISR）**。（画重点）
3. 接下来，就是cpu陷入内核，通过寄存器来完成跳转地址，来执行特定的代码，这里就是继续执行进程。

是不是很麻烦，其实可以理解成为信号的产生，保存和处理，其实是很像的。


>- 中断向量表 **本质**：它是一个存储在内存中的**数组**或**表格**。
>- **作用**：表格的每一项（称为一个“描述符”或“入口”）都对应一个**中断号**，并存储着处理该中断的**程序（称为中断处理程序或中断服务例程）的起始地址**。

三个注意点:
>- 中断向量表就是操作系统的⼀部分，启动就加载到内存中了  
>-  通过外部硬件中断，操作系统就不需要对外设进⾏任何周期性的检测或者轮询  
>-  由外部设备触发的，中断系统运⾏流程，叫做硬件中断

## 3-2 时间中断:
有了上面的理解,我们就能详细的看待时间中断:
在之前的理解之中:进程是被操作系统唤醒的,在组织的(先描述后组织),无论是哪个状态还是在哪个队列里面,都是被操作系统给操作的(O(1)算法,里面一个结构体通过不同的链表指针操作),那么我们就有一个问题了 : 操作系统又是怎么被调度的呢?

其实,在我们的猜想里面我们只需要在外部设备里面加一个时钟源,就可以了,让他定时的产生电信号 .这样我们就在时钟源的驱动下,  操作系统不就在硬件的推动下，⾃动调度了么！
由于源代码非常难以理解,我们只给出一部分来自己查看:
```cpp
// kernel/sched/core.c [^2^][^12^]
void scheduler_tick(void)
{
    int cpu = smp_processor_id();
    struct rq *rq = cpu_rq(cpu);           // 获取当前 CPU 运行队列
    struct task_struct *curr = rq->curr;   // 获取当前运行进程
    
    /* 更新当前进程虚拟运行时间 (vruntime) */
    curr->sched_class->task_tick(rq, curr, 0);  // 调用具体调度类的 tick 处理
    
    /* 检查是否需要抢占（时间片耗尽） */
    if (curr->sched_class != &idle_sched_class) {
        /* 唤醒软中断，可能触发 schedule() */
        if (test_thread_flag(TIF_NEED_RESCHED))
            set_tsk_need_resched(curr);
    }
    
    /* 更新 CPU 负载统计 */
    calc_global_load_tick(rq);
}
```

## 4. 理解Linux系统的运行:
1. 主板上有一个专门的硬件定时器芯片（比如早期的 PIT 8253/8254，或者现代多核 CPU 内部的 Local APIC Timer）。
2. 操作系统在开机或者启动进程前，会给这个硬件定时器编程：**“老兄，每隔 1 毫秒（或者 10 毫秒），你必须雷打不动地给 CPU 发送一个电信号（IRQ0）。”**这个电信号，就是**时钟中断**。它是由纯硬件周期性触发的，**任何软件（包括你的死循环）都拦不住它**。
3. 操作系统设置好闹钟后，就把 CPU 的控制权交给了你的 C++ 程序，并且把 CPU 的特权级降到了 Ring 3（用户态）。我的程序还在循环着.
4. CPU 硬件有一个极其霸道的底层逻辑：**只要收到中断信号，管你现在在干嘛（哪怕是在死循环），立刻无条件暂停当前指令！**
5. **调度：** 操作系统调用自己的**进程调度器（Scheduler）**。调度器一看，后面还有个微信和网易云音乐在排队呢。
6. **换人：** 操作系统把刚才保存的 C++ 死循环的现场，彻底收起来存到进程控制块（PCB）里。然后把微信进程的现场拿出来，恢复到 CPU 寄存器里。
7. **继续躺平：** 操作系统执行 `iret` 指令，退出内核态，把 CPU 控制权交给微信进程。然后，操作系统**再次躺平**。

这个大概就时系统的被调度.现代操作系统本质上是一个**“中断驱动（Interrupt-Driven）”**的怪物。它平时绝不主动干活（躺平），完全依靠**硬件中断**（鼠标动了、硬盘读完了、尤其是**时钟定时器到了**）来强行唤醒它。时钟中断就是操作系统能掌控全局的底气，没有它，任何一个普通的 `while(1)` 都能把整个电脑直接卡死。
